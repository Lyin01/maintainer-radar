# Governance

Maintainer Radar starts with a small maintainer model and is intended to grow into a community-maintained tool for open-source maintainers.

## Roles

- Primary maintainer: owns releases, security response, roadmap, and final review decisions.
- Core maintainer: reviews changes, triages issues, and can approve releases when delegated.
- Contributor: submits issues, docs, examples, and code changes.

## Decision Making

The project favors rough consensus with written rationale in issues or pull requests. For decisions that affect safety, data handling, or AI integration, maintainers should document the tradeoffs before merging.

## Release Policy

- Patch releases may include bug fixes, rule tuning, and docs.
- Minor releases may add report formats, integrations, and new scoring signals.
- Breaking changes require a migration note and schema version bump.

## Maintainer Load

This repository should use its own automation. Maintainers are encouraged to publish periodic triage reports generated by Maintainer Radar so contributors can see how decisions are made.
